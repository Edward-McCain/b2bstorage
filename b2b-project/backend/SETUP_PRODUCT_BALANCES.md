### 3. Проверка работы
После выполнения SQL запросов система должна:

1. Отслеживать остатки товаров на складах
2. Показывать доступные товары при создании перемещений
3. Обновлять остатки при проведении операций

## Структура таблиц:

### product_balances
- `id` - уникальный идентификатор
- `product_id` - ID товара (связь с products_sklad)
- `warehouse_id` - ID склада (связь с warehouses)
- `quantity` - количество товара на складе
- `created_at`, `updated_at` - временные метки

### product_operations
- `id` - уникальный идентификатор
- `product_id` - ID товара
- `warehouse_id` - ID склада
- `operation_type` - тип операции (receipt, write_off, transfer_in, transfer_out, inventory)
- `quantity` - количество (положительное для приходов, отрицательное для расходов)
- `reference_type` - тип документа (receipt, write_off, product_transfer, inventory)
- `reference_id` - ID документа
- `notes` - примечания
- `created_by` - ID пользователя, создавшего операцию
- `created_at`, `updated_at` - временные метки

## Примечания:
- Система автоматически обновляет остатки при проведении оприходований
- При создании перемещений проверяется достаточность товаров на складе-отправителе
- Все операции логируются в таблице product_operations для аудита
