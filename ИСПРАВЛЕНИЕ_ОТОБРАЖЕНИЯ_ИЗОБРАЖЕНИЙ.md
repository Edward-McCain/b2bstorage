# Исправление проблем с отображением изображений

## Проблема
При загрузке изображений товаров на фронтенде отображалась "Ошибка загрузки" вместо реальных изображений, хотя файлы успешно загружались на сервер.

## Анализ проблемы

### Что происходило:
1. **Backend возвращал относительные пути** вместо полных URL:
   ```json
   {
     "image": {
       "id": 46,
       "image_url": "uploads/products/product_688090ca384589.48671163.webp"
     }
   }
   ```

2. **Frontend формировал неправильные URL**, добавляя `/storage/` к уже готовым путям:
   ```javascript
   // Результат: http://site.com/storage/uploads/products/...
   // А должно быть: http://site.com/storage/uploads/products/...
   ```

### Корень проблемы:
В методе `uploadImage()` контроллера НЕ вызывался `transformImageUrls()` для преобразования относительного пути в полный URL.

## Исправления

### 1. Backend - ProductController.php

**До исправления:**
```php
public function uploadImage(Request $request, $id)
{
    // ... логика загрузки ...
    
    $img = ProductImage::create([
        'product_id' => $product->id,
        'image_url' => $path, // "uploads/products/file.webp"
        'alt_text' => $request->alt_text ?? '',
    ]);
    
    return response()->json(['image' => $img], 201); // ❌ Возвращает относительный путь
}
```

**После исправления:**
```php
public function uploadImage(Request $request, $id)
{
    // ... логика загрузки ...
    
    $img = ProductImage::create([
        'product_id' => $product->id,
        'image_url' => $path,
        'alt_text' => $request->alt_text ?? '',
    ]);
    
    // ✅ Преобразуем URL изображения в полный URL
    $images = collect([$img]);
    $transformedImages = $this->transformImageUrls($images);
    
    return response()->json(['image' => $transformedImages->first()], 201);
}
```

### 2. Frontend - ImageDropzone.vue

**Функция `imageSrc()` была корректной** и правильно обрабатывала как полные URL, так и относительные пути:

```javascript
function imageSrc(img) {
  // Если URL уже полный (начинается с http), возвращаем как есть
  if (img.image_url && (img.image_url.startsWith('http://') || img.image_url.startsWith('https://'))) {
    return img.image_url // ✅ Возвращает полный URL
  }
  
  // Обработка относительных путей для совместимости
  const imagePath = img.image_url || img.image_path
  if (!imagePath) return ''
  
  let cleanPath = imagePath.startsWith('/') ? imagePath.substring(1) : imagePath
  
  let fullUrl
  if (cleanPath.startsWith('storage/')) {
    fullUrl = `${window.location.origin}/${cleanPath}`
  } else {
    fullUrl = `${window.location.origin}/storage/${cleanPath}`
  }
  
  return fullUrl
}
```

Теперь при загрузке изображения:

   ```json

       "id": 46,
       "image_url": "http://site.com/storage/uploads/products/product_xxx.webp"
     }
   }
   ```

2. **Frontend правильно отображает изображение:**
   - Полные URL используются как есть
   - Нет ошибок загрузки
   - Изображения отображаются корректно

3. **Консистентность API:**
   - `uploadImage()` теперь возвращает тот же формат URL, что и `getImages()`
   - Все методы контроллера используют `transformImageUrls()`

## Техническое объяснение

Laravel сохраняет файлы в `storage/app/public/` и делает их доступными через симлинк `public/storage/`. 

**Правильный flow:**
1. Файл сохраняется: `storage/app/public/uploads/products/file.webp`
2. В БД сохраняется путь: `uploads/products/file.webp`  
3. `transformImageUrls()` формирует полный URL: `http://site.com/storage/uploads/products/file.webp`
4. Frontend получает готовый URL и отображает изображение
